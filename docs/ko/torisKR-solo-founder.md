## 1. 실제 경험에서 추린 여섯 가지 기준

아래는 2026-10-15에 읽은 기존 암묵지 노트의 요약이다. 원본 노트의 수정일은 2026-10-14이다. 원본 실행 결과를 새로 재검증한 것은 아니다.

### D01. 깨끗한 작업 폴더보다 내 변경의 경계가 중요하다

여러 AI와 작업한 저장소에는 시작부터 다른 수정이 있을 수 있다. 작업 전 상태를 기록하고 담당 파일을 정한다. 전달할 변경만 검토한다. 정리한다는 이유로 다른 수정까지 지우거나 일괄 스테이징하지 않는다. 같은 파일을 동시에 수정했다면 파일 목록만으로 안전하다고 판단하지 않는다.

### D02. 완료를 하나의 상태로 말하지 않는다

구현, 로컬 검사, 실제 화면 조작, CI, 배포 접수, 공개 반영, 사업 성과는 각각 다른 증거가 필요하다. 타입 검사만 했다면 화면 검증은 미실행이다. 빌드에 성공해도 배포된 것은 아니다. 이번 작업에서 실행한 단계와 남은 단계를 분리한다.

### D03. 검색 메타데이터는 원문이 알고 있는 사실만 말한다

경고를 없애려고 작성자·수정 시각·단어 수·본문 이미지를 만들어 넣지 않는다. 원문, 화면, 검색용 데이터가 같은 사실을 사용하도록 맞춘다. 필요한 정보를 보강하려면 실제 콘텐츠부터 추가하고 그 내용으로 메타데이터를 만든다.

### D04. 배포 성공 뒤에도 실제 주소를 확인한다

소스 커밋, 배포 산출물, 대상 환경, 실제 주소의 응답을 대조한다. 예전 내용이 나온다고 바로 캐시 문제로 단정하지 않는다. 같은 실제 주소에서 의도한 내용과 동작을 확인한 뒤 공개 반영을 보고한다. 과거 실패 기록과 최신 성공도 구분한다.

### D05. 결제창 도달은 구매 성공이 아니다

상품 조회 → 결제창 → 구매 → 권리 지급 → 복원을 나눠 기록한다. 실제 사례에서는 결제창을 연 뒤 사용자의 지시에 따라 취소했고 구매·권리 지급은 미검증이었다. 설치 빌드, 서명·트랙, 기능 플래그가 다르면 같은 조건의 검증으로 묶지 않는다.

### D06. 실행 앱·중계·모델·작업 결과를 구분한다

OpenCodex에 기록된 provider가 특정 편집기와 관련 있다고 그 편집기에서 작업했다고 판단하지 않는다. HTTP 성공은 응답 성공이지 코드나 배포의 성공이 아니다. 연결 근거가 있을 때만 같은 작업으로 묶으며, 여러 기록을 여러 성과로 중복 계산하지 않는다.

## 2. 1인 운영에 적용할 추가 기준

이 부분은 기존 지침·과거 선호와 새 운영 제안을 구분해서 사용한다. 검증된 매출 공식이나 최신 도구 순위가 아니다.

| 기준 | 실제 적용 |
|---|---|
| D07. 직접 만들기 전에 기존 해법 확인 | 충분한 기존 도구가 있는지 먼저 보고, 비용뿐 아니라 유지보수·지원 부담까지 비교한다. 결제를 자동 승인하지 않는다. |
| D08. 선택한 운영 모드 존중 | 단독 에이전트 요청이면 다른 도구 위임을 기본 전제로 삼지 않는다. 병렬 작업은 요청과 필요가 있을 때만 추가한다. |
| D09. 기능 개수보다 실제 작업 흐름 평가 | 메모리, 반응성, 프로젝트·세션 관리, 원격 접근, 편집 필요, 에이전트 호출 편의를 실제 조건으로 평가한다. |
| D10. 사실 기획서는 하나, 채널 표현은 따로 | 같은 제품 변경을 Threads·X·네이버·LinkedIn 목적에 맞게 다르게 구성한다. 게시 승인과 실제 게시 결과는 별도다. |
| D11. 기능 확대 전에 지속·수정·중단 조건 결정 | 고객 문제, 유입 경로, 최소 결과, 비용·시간 한도, 판단에 필요한 신호를 먼저 적는다. 수치가 없으면 모른다고 남긴다. |
| D12. 대화 전체 대신 조건부 판단을 축적 | 상황·실제 결정·실행·결과·한계·재사용 조건을 남긴다. 제안만 한 내용은 검증된 지식으로 승격하지 않는다. |

## 3. 작업을 시작하고 끝내는 흐름

```text
요청과 현재 프로젝트 맥락 확인
→ 기존 결정·관련 암묵지 조회
→ 고객 문제·작업 범위·수용 증거·비용 한도 정의
→ 의존성에 따라 작업 분리
→ 허용된 로컬 작업 실행
→ 변경 위험에 맞는 검사
→ 완료 단계별 증거와 미검증 범위 보고
→ 실제 교훈만 기존 지식에 병합
```

공유 checkout에는 기본적으로 수정 담당을 한 명 둔다. 병렬 작성이 필요하면 담당 경로와 격리된 작업 공간을 정하고, 같은 파일·의존 작업은 직렬화한다. 이 문서가 DAG 실행기나 자동화를 설치한 것은 아니다.

## 4. 1인 사업에서 빠뜨리지 않을 질문

**제품 선택:** 누가, 어느 순간, 어떤 불편을 겪는가? 지금 무엇으로 해결하는가? 첫 사용자를 어디서 만날 수 있는가? 기능이 아니라 끝까지 작동하는 최소 사용자 흐름은 무엇인가?

**수익화:** 결제 기능 구현과 지불 의사는 별도다. 실제 수입·환불·수수료·변동비·고정 운영비를 같은 기간으로 비교한다. 이미 수수료가 빠진 수입에서 같은 수수료를 다시 빼지 않는다. 지원 시간과 운영 부담도 기록한다. 세금·정산 규정·요금은 실제 결정을 할 때 최신 근거로 확인한다.

**성장:** 조회수, 클릭, 설치, 첫 가치 경험, 재사용, 결제는 다른 지표다. 비율에는 기간과 분모를 붙인다. 바이럴은 보장이 아니라 실제 공유 행동으로 검증할 가설이다.

**운영:** 사용하지 않는 고급 기능 때문에 도구 복잡도를 늘리지 않는다. 작업과 사업의 상태가 바뀌면 기존 결정의 날짜와 적용 범위도 갱신한다. 종료한 제품을 자동으로 다시 활성화하지 않는다.

## 5. 여섯 도구에 전달하는 방법

| 도구 | 이번에 정리한 내용 | 남아 있는 한계 |
|---|---|---|
| Codex | 기존 변경 보존, 증거 기반 완료, 콘텐츠 정합성 | 원본 세션·현재 설정 재열람 없음 |
| OpenCodex | 중계와 실제 실행 출처 구분 | 현재 중계 상태·모델·독립 스킬 로더 확인 없음 |
| Hermes | 과거 단독 운영 요청, torisKR 명칭, 의존성·지식 축적 목표 | 현재 설정·Gateway·실행 성공 확인 없음 |
| Grok | 과거 콘텐츠 역할 통합 요청과 채널별 기획 | 봇 변경·게시·현재 연동 확인 없음 |
| agy | 과거 CLI 활용 맥락과 도구 선택 기준 | 실행 파일·버전·세션·설정 확인 없음 |
| Claude | 로컬 완료와 배포 승인 분리, 실제 주소 검증, 지식 정제 | 원본 세션·현재 설정 재열람 없음 |

OpenCode와 OpenCodex는 다른 이름으로 유지한다. `agy`를 확인 없이 다른 CLI 이름으로 바꾸지 않는다. 기존 결제 경험의 실행 앱은 Cursor로 기록되어 있으므로 요청한 여섯 도구 중 하나의 경험으로 바꿔 쓰지 않는다.

로컬 파일을 읽을 수 있는 도구에는 다음처럼 요청한다. 파일 접근이 없는 인터페이스에는 필요한 공개 가능 부분만 전달한다. 이 문서를 전달했다고 자동 설치·연동이 완료되는 것은 아니다.

```text
~/projects/product-growth-skills/toris-solo-founder/SKILL.md를 읽고 적용해.
지금 선택한 에이전트와 프로젝트 지침을 유지해.
이번 요청의 결과, 수정 범위, 수용 증거, 비용 한도를 정리하고
허용된 로컬 작업을 실행해.
확인한 결과와 미검증 범위를 구분하고,
재사용할 교훈이 실제로 생겼을 때만 지식 카드로 남겨.
한국어로 보고해.
```

새 아이디어 검토에는 제품 계약서, 개발에는 의존성 카드와 검증 보고서, 콘텐츠 작업에는 채널 기획서, 작업 종료에는 암묵지 카드를 사용한다. 이 문서만으로 유료 서비스, 전역 설정, 계정, 게시, 배포, 자동화, 커밋·푸시를 변경하지 않는다.

## 6. 검증의 의미

구조 검사는 파일·링크·메타데이터·언어 구분·일부 비밀정보 패턴을 확인한다. 실제 여섯 도구에서의 스킬 호출이나 지침 준수를 보증하지 않는다. 행동 검증 시나리오는 별도 문서에 있으며, 런타임별 실험은 이번 정리에 포함되지 않았다.

로컬 검사 명령:

```bash
python3 scripts/validate_skills.py
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s scripts -p 'test_validate_skills.py'
bash toris-flutter-play-store-release/tests/run_tests.sh
```

2026-10-15 실행 결과: 전체 스킬 8개 구조 검사, 새 회귀 테스트 10개, `git diff --check`는 통과했다. 개인 원장이 Git 제외 대상인 것도 확인했다. 다만 기존 릴리스 패키지 테스트는 `FAIL: unexpected package file: .DS_Store`로 중단됐다. 해당 파일의 수정일은 2026-07-28이며 기존 릴리스 패키지의 추적 파일은 이번에 변경하지 않았다. 그 뒤의 테스트는 미실행으로 남겼고 기존 파일은 삭제하지 않았다.

정리 이후 생긴 경험도 기존 지식의 근거·한계를 유지하며 병합한다. 개인 원본 경로와 상세 결정은 로컬 전용 기록에 남기고, 공유는 별도 검토한 내용만 대상으로 한다.
