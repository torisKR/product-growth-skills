## Record schema

For a future authorized harvest, capture only the minimum necessary:

```text
source_key:
observed_at:
event_date:
source_type: raw-output | curated-note | user-directive | assistant-report
execution_app:
relay:
requested_model:
resolved_provider_model:
project_alias:
correlation_evidence:
action_requested:
action_observed:
artifact_or_check:
verified_stage:
limitation:
privacy_class: private | sanitized-shareable
```

Missing fields remain unknown. A provider returning HTTP success does not prove implementation, testing, commit, release, or a business result. A model name in a request is not necessarily the model actually selected. Different records are linked only through direct correlating evidence, not similar wording or close timestamps alone.

## Safe knowledge collection

Read curated memories and project receipts before searching large histories. Keep an explicit source allowlist and a bounded query. Never copy auth files, environment secrets, cookies, private keys, signing material, payment details, customer data, or entire logs into a shared skill.

A denied root is a boundary. Do not bypass it through another shell, symlink, or connector. Record the denied or uninspected scope and continue using authorized sources. Empty search results mean no match within the searched scope, not proof that no record exists.

Preserve original files. Merge duplicates by event/artifact evidence. Keep private source pointers separate from the reusable rule. Do not treat an installed third-party skill, an assistant's suggestion, or a source-code adapter as proof that the owner performed that workflow.

## Use across tools without pretending installation happened

This collection adds a skill package and reference documents only. It does not change global instructions, install symlinks, reconfigure providers, connect bots, or create schedules.

Mentioning a tool in a knowledge-harvest request does not authorize reinstalling it or reversing an earlier removal decision. For any tool with authorized local file access, supply the package's SKILL.md and the relevant reference path. For an interface without file access, provide only the needed sanitized text. Confirm its actual skill-discovery and attachment behavior before claiming a native integration.

In particular, no independent OpenCodex skill loader or Grok filesystem integration was established by this collection. Runtime-specific invocation, installation paths, and compatibility need separate verification. Follow the owner's currently selected single-agent or multi-agent mode rather than imposing a permanent routing table.
